# Two-workspace contract — native EA correction

User rejected v0.1: two separate workspaces; actual tool calling and context; richer causal data; independently running EA manager. Root owns all backend/strategy/risk/EA code. UI child owns only fusion/static/*.

## UI design
Purpose: operate and inspect two trading workflows without implementation slogans. Industrial/utilitarian terminal; palette #101715 #EBEDE5 #D6B56D #55B69A #D87569. Fonts Bahnschrift, Microsoft YaHei, Consolas. Narrow left navigation, wide work area, contextual right details. No hero, marketing, repeated warnings or dense dashboard card grid. Main nav exactly AI交易 / EA工作室. Secondary settings/history drawers.

## Implemented v2 endpoints
- POST /api/workspace/select {module: "ai"|"ea"}: stopped-only execution ownership switch, exactly one module trades at a time.
- GET /api/pipeline -> {run_id,module,status,stage,nodes:[{id,label,state,depends_on,thinking,started_at,finished_at,result,tools}],packet}. Always AI module; persisted independently of EA cycles. States pending/running/done/error/skipped, actual progress. Waiting for a new bar preserves prior completed graph. Packet contains per-timeframe computed indicators, provenance, data quality. Flow MT5+indicators -> market -> background -> judge -> risk -> gateway. Node result summary/evidence/uncertainties; tool records name,args,result,duration.
- GET /api/background -> {updated_at,news,events,providers,coverage_note}; POST /api/background/refresh same output.
- GET /api/ea/workspace -> {running,bridge,settings,signal,review,proposal,last_backtest,conversations}. settings is active ea config. bridge is native FUSION_EXEC1: connected/reason/read_only=false/instance_id/entries_enabled/pending/state/protection/strategy_revision/command_revision/lease_until/positions/magic/calendar_fresh. companion retains old FUSION3 telemetry. entry_decision carries enabled/reason/expires_at/risk_scale; parameter_export carries published revision. signal includes action,reason,indicators,context. review includes busy,last_error,last_review_at. proposal may be null or {id,patch,status,reason,validation}. conversations[{id,title,updated_at}].
- POST /api/ea/conversations {title?} -> {id,title}; GET /api/ea/conversations/{id} -> {id,title,messages:[{id,role,content,created_at,tools?}]}; POST same /messages {message} -> asynchronous job {id,status}; GET /api/ea/jobs/{id} -> {id,status,result,error?}. Poll job then reload transcript. Tool trace is visible, raw reasoning is not exposed.
- POST /api/ea/review -> asynchronous job; POST /api/ea/backtest -> asynchronous job. POST /api/ea/parameters/export -> typed EA params revision.

## Behavior
Trading starts only by Start after demo Arm; all restarts stopped/disarmed. EA chat/review/backtest work while stopped, independently of Codex. EA manager never orders; FusionExecutor owns M1 entry/close/SLTP in MT5. AI only grants bounded entry permission inside a user-started demo session and proposes validated parameters. Python native cycles only supervise. Stop/disconnect pauses entries while native protection continues; new EA boot stops the session. Native pause acknowledgment, flat account, evidence and matching config versions are required before parameter publication; matching native revision is required before saving the active profile. See NATIVE-EA.md. Current terminal attachment is NOT verified for the new executor. Never fake progress, backtest performance, connected bridge, or AI response.

EA settings additionally: execution_magic (distinct from risk.magic), entry_lease_seconds, ai_controls_entries, decision_ttl_minutes, require_calendar. /api/ea/parameters/export is now stopped/flat native configuration export; /api/positions/{ticket}/close queues native-owned tickets to the EA, never Python send. Native cycles report status=native_monitor; running means the manager is running, not that entry permission is enabled.

Workspace review additionally carries active_job/latest_job (nullable), conversation_id and next_review_at (interval/permission scheduling estimate, not a guarantee). Public jobs contain id/kind/status, created_at/finished_at, conversation_id, model/thinking, timestamped model_config/model_running/model_done/tool_running/tool_done events, error/result_summary/usage/latency_ms. Job states: running/completed/error/cancelled/interrupted. Failure results cannot become completed; final message failure does not undo previously confirmed tool effects. Restart preserves public evidence and marks unfinished work interrupted. Never expose private model protocol/reasoning. UI must support absent fields on older running servers and show missing progress honestly.

AI output_token_policy: model_max (default, GET provider /models and use matching max_output_tokens), fixed (max_tokens), provider_default (omit max_tokens). No cumulative token quota. Unavailable model metadata produces an actionable visible error; no invented capability or arbitrary automatic fallback.
