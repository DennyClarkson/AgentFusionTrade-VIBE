# 原生 EA：交易与 AI 管理

AI 交易模块通过 Python 下单；EA 工作室通过 FusionExecutor 在 MT5 内下单、平仓、保本和移动 SL/TP。Python 的 EA 模拟实单路径只监督、发送参数和开仓许可，不调用经纪商下单/保护函数。影子模拟和历史回测仍在 Python 中。

## 挂载一次

FusionBridge 是可选的行情/日历组件，不能替代交易 EA。仓库提供源码 `integrations/mt5/FusionExecutor.mq5` 和同目录 `FusionKernel.mqh`，不分发编译后的 `.ex5`；首次克隆需要用 MetaEditor 编译。这是固定模板实现，不执行模型生成的任意代码。

首次使用按 README 安装并启动工作台。以后更新 Python 源码时，需要重启工作台 **Python 进程**：在停止、未解锁、空仓状态，关闭本项目启动窗口；若后台运行，在任务管理器按命令行确认本目录的 `run.py` 进程后结束它，再双击项目的 `Start-Fusion.cmd`。不要结束其他 Python 服务。刷新网页或点击交易“停止”按钮都不等于重启应用进程；重复启动脚本会复用仍在运行的旧服务。

1. MT5“文件 → 打开数据文件夹”，在 `MQL5/Experts` 下创建 `AgentTradeFusion` 文件夹。
2. 将仓库的 `FusionExecutor.mq5` 与 `FusionKernel.mqh` 一起复制到该文件夹，用 MetaEditor 打开 `.mq5` 按 F7 编译；确认无错误并生成 `FusionExecutor.ex5`。更新源码时重复此步骤，并在没有框架持仓时重新挂载 EA。
3. 刷新导航器，在一个 XAUUSD 图表挂载 **FusionExecutor**。建议 M1 图表；计算独立读取已收盘 M1/H1/D1，不取决于显示周期。只挂一份，第二实例会被互斥文件拒绝。FusionBridge 如需保留，请放在另一个图表。
4. 工作台 EA 工作室应显示“FusionExecutor 已连接”。点击“发布原生 EA 参数”发送完整策略和风险配置，在“参数与执行详情”中等待 **EA 已确认应用**。
5. 先确认没有其他模块运行；若右上角显示循环运行中，打开“执行控制”点击“停止 / 锁定”，等当前分析结束。在 EA 工作室点击“设为启动模块”，并确认“执行控制”里的启动模块是“EA工作室”。浏览页面不会自动切换启动模块。
6. 核对当前模拟账户登录号，点击“解锁模拟盘”，再点击“启动 AI 管理”。需要立即评估时，关闭弹窗后点击右侧“后台复盘”，避免等待下一次定时复盘。AI 根据当前行情和背景决定允许或暂停开仓，不保证启动后立即成交。

就绪应同时满足：原生 EA 已连接、参数版本已确认且不为 0、启动模块为 EA工作室、AI 管理运行中。实际入场还需要 AI 许可、EA 信号和日历/时段/风险检查全部通过。若显示“循环运行中”但启动模块是 AI交易，运行的是另一套模块，应先停止后切换。

工程验证曾确认原生连接、匹配参数回执、日历和 AI 活动；这不代表新安装已就绪。每个终端应以当前工作台和 MT5 日志为准。原生成交、保护生命周期及跨行情一致性仍需验收。

## 手动设置允许交易时间

EA 工作室顶部的 **允许交易时间** 可直接选择北京时间或 UTC，按整点设置开始/结束，或勾选“全天允许”。结束时间不包含在窗口内；结束早于开始表示跨午夜。原预设 UTC06–21 对应北京时间14:00–次日05:00。时区选择只改变显示，保存统一使用 UTC。“周末停止交易”按 UTC 周六/周日执行，即北京时间周六08:00至周一08:00。

修改后点 **暂停管理并保存时段**（已经停止时显示“保存并发布到 EA”）。需要空仓、无挂单/未确认交易且 EA 已连接。应用暂停管理，等待本轮任务结束和 EA 暂停回执，再保存新版本、发布并等待 EA 确认；确认后在“执行控制”重新解锁并启动 AI 管理。失败会区分“未修改”和“已保存但应用未确认”。出现其他窗口版本冲突时，点“恢复已保存时段”重新加载，再设置。

此窗口同时用于 AI 交易和 EA 执行；到结束时间会触发框架持仓退出。面板下方还显示风险预算为0的时段，点“时段风控设置”可编辑风险方案；当前换日时段北京时间05:00–08:00预算为0，所以“全天允许”也不会覆盖它。AI 许可、新闻、信号和市场开放检查仍独立生效。

## 在哪里看 AI 工作

EA 工作室顶部“AI 管理活动”显示当前任务、模型/思考选项、调用阶段、真实工具记录、耗时和最近结果；“查看自动复盘对话”打开保存的完整报告。刷新页面后会恢复正在运行的任务，不必重复发起复盘。AI 仅在发起任务时调用模型，管理循环运行中不代表模型持续生成内容。失败会明确显示，不能把失败当作已允许交易。

程序不限制累计 token 用量。AI 配置“单次输出策略”默认“使用模型最大输出额度”，向供应商读取该模型声明的最大值；“自定义单次上限”才使用数值 max_tokens。供应商未提供模型上限时，选择“使用服务默认”或自定义。单次响应仍受供应商能力和上下文窗口限制；过期交易判断仍不能下单。配置升级会在下一次 Python 启动时保存新版本。能力字段依据 [DeepSeek Models API](https://api-docs.deepseek.com/api/list-models/)，不把文档里的数值写死在运行代码中。

## AI 与停止语义

EA 管理 AI 使用独立模型、思考选项、提示词和持久对话。实际工具包括行情、背景、成交复盘、候选回测、参数建议和 `set_entry_permission`。

- 允许开仓前，AI 必须在本轮读取行情和背景。只能在用户已解锁、启动的 EA 模拟盘会话内授予许可，不能自行解锁、切换账户或重启已停止会话。
- 许可带时限和 0..1 风险系数。EA 仍独立检查信号、最小手数、预算、日历、事件窗口和交易时段；许可不等于成交。
- 用户停止、AI 暂停、许可过期或 Python 断开后，停止开新仓。**EA 留在图表上时继续保护已有持仓**；移除 EA 或关闭 MT5 后，只剩经纪商已有 SL/TP。
- Python 或 EA 重启不自动恢复开仓。EA 实例变化时，旧 AI 许可不会续给新实例。
- 原生 EA 使用独立 Magic。只有新鲜暂停回执、空仓且无未确认交易时，才能切回 Python；不能仅凭心跳超时接管。

## 参数应用

AI、提示词、策略、风险和执行配置仍独立存储版本。AI 仅能修改允许范围内的策略数值，不能提高硬风险或改变账户。

自动调整依次经过：候选回测 → 幅度、版本及有效期校验 → 暂停回执和空仓 → 发布完整参数包 → EA 校验并持久保存 → 匹配版本回执 → 保存新活动配置。界面区分待暂停、已发布、已应用。失败或过期建议不作为完成。

## 原生约束

- 仅 USD 模拟账户，绑定账户/服务器，独占本机公共文件锁。不同机器上的同一账号不受本机锁约束。
- 明确 M1 趋势只顺向；震荡采用 H1/D1 背景，布林外轨触及后收回确认。
- 按 ATR、时段和已知高影响事件调整距离与预算；使用 OrderCalcProfit、佣金和不利滑点估计风险，手数向下取整，并受剩余日亏损预算和保证金限制约束。
- 检查日历最近成功查询、事件窗口、点差、报价/闭合 K 线、敞口、权限及止损冻结距离。日历查询成功不代表事件覆盖完整。
- 持久保存已使用信号和交易意图后才发送。结果不明确时按持仓/历史证据核对，不盲目重发。状态损坏或丢失且已有交易证据时锁定新执行。
- 初始 SL/TP 随单提交；盈利后只收紧止损。最长持仓、时段和事件退出独立于 AI 许可。配置损坏时明确显示仅剩经纪商保护，不冒充本地追踪有效。

止损风险是估计，跳空/滑点可能超过预算。原生逐笔执行与历史回放尚未完成跨行情一致性验收，现有回测也未证明策略稳定盈利。

## 文件与验证

公共目录 `MetaQuotes/Terminal/Common/Files/AgentTradeFusion`：`execution.csv` 为完整配置；`control.csv` 为实例限定许可/平仓请求；`executor.csv` 为 FUSION_EXEC1 状态与回执；`executor.active.csv` 为保护恢复配置；`executor.owner.lock` 为独占锁；`native_*_state.csv`、`native_*_journal.csv` 为执行状态/审计。

不要通过删除状态或未确认记录恢复交易。先按原始账户的订单、成交和 SL/TP 证据核对，无法证明时保持阻止。备份应用 SQLite 和公共协议目录。

Python 验证：`.venv/Scripts/python.exe -m pytest -q`，原生控制边界测试见 `tests/test_native_ea.py`。编译/单测不等于挂图成交或盈利验证。
